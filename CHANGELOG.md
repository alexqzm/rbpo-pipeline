## [Unreleased]

### Добавлено
- Повторно используемый рабочий процесс `rbpo.yml`: задачи analyze, build, rebuild, verify, report;
  права токена заданы для каждой задачи, действия закреплены SHA коммита.
- Шестнадцать технических артефактов ГОСТ Р 56939-2024 с трёхзначными состояниями (P, N, F):
  5.4.3.3, 5.10.3.2–5.10.3.4, 5.12.3.2, 5.13.3.4–5.13.3.6, 5.14.3.3, 5.16.3.2, 5.16.3.4, 5.17.3.5,
  5.18.3.2, 5.18.3.3, 5.20.3.2, 5.20.3.4.
- Разметка срабатываний SAST и уязвимостей зависимостей (`.rbpo/triage.yaml`) с обоснованием и
  сроком действия; решения записываются в SARIF как подавления.
- Организационные артефакты по документам проекта (`rbpo.yaml`, раздел `organizational`).
- Манифест и отчёт о полноте свидетельств через rbpo-evidence, опись комплекта с SHA-256,
  сводка запуска, решение по выпуску; аттестация архива комплекта.
- Командная строка `rbpo-pipeline` для запуска шагов вне GitHub Actions.
- Демонстрационный проект `examples/demo-app` и самопроверка на нём.
- Работа с ИИ-агентом: агент предлагает разметку, решение переносит человек. Команды `triage-queue`
  (очередь разметки), `proposals-check` (проверка предложений агента по правилам ПП01–ПП11: формат,
  соответствие комплекту свидетельств, запрет шаблонов и принятия риска, ссылки на код с дословной
  цитатой, срок пересмотра) и `agent-guard` (ветка агента меняет только каталог предложений).
- Набор для агента в каталоге `agent/`: правила, скилл `rbpo-triage`, журнал ошибок, программа и
  методика испытаний, стенд с известными ответами и ловушками, пример рабочего процесса контроля
  ветки агента. Описание со схемами и требованиями к обвязке агента — `agent/README.md`,
  справочник — `docs/agent.md`.

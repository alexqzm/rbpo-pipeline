# Правила состояний артефактов

Каждый шаг конвейера пишет запись `states/<артефакт>.json`: состояние (P, N, F), файлы-основания
в комплекте, числа (`summary`), пояснение (`note`) и признак `error`, если свидетельство не
получено из-за сбоя инструмента. Ниже — когда шаг ставит каждое состояние. Если шаг не
выполнялся, в манифест попадает N с пояснением «шаг конвейера не выполнялся».

## 5.4.3.3 Свидетельства контроля изменений ПО и документации

Шаг `source`. Диапазон изменений определяется событием GitHub Actions:

| Событие | Диапазон |
|---|---|
| `pull_request` | база запроса .. последний коммит запроса |
| `push` тега | предыдущий тег .. текущий тег |
| `push` ветки | состояние ветки до отправки (`before`) .. текущий коммит |
| прочие | последний тег .. текущий коммит; без тегов — последний коммит |

Записываются коммиты (автор, дата, тема, локальный статус подписи) и изменённые файлы с
признаком «в каталоге проекта» и видом (документация — `.md`, `.rst`, `.txt`, `.adoc`, `.tex`,
`.odt`, `.docx`, `.pdf` и всё в каталогах `docs/`, `doc/`; остальное — ПО). Не более 250 коммитов.

- **P** — диапазон определён, коммиты получены.
- **N** — нет репозитория git.

## 5.10.3.2–5.10.3.4 Статический анализ

Шаг `sast` по SARIF и JSON-выводу Semgrep.

Уровень срабатывания — `level` результата SARIF, иначе уровень правила по умолчанию, иначе
`warning`. Решение из файла разметки ищется по шаблонам правила и пути (и строке, если указана);
решение с истёкшим `until` не действует и попадает в анализ неустранённых ошибок как истёкшее.
Ложные и принятые срабатывания получают в SARIF подавление `{"kind": "external", "status":
"accepted", "justification": …}`; у каждого срабатывания в `properties.rbpoTriage` — решение или
`untriaged`.

**5.10.3.4 отчёт с разметкой**
- **F** — есть срабатывание не ниже порога `sast_fail_on` без решения или с решением `confirmed`.
- **P** — иначе.

**5.10.3.2 перечень инструментов.** Языки проекта определяются по файлам, которые отслеживает git
(по расширению). Язык покрыт, если среди файлов, разобранных анализатором (`paths.scanned`), есть
файлы этого языка.
- **F** — есть язык без анализа и без обоснования в `sast_exclude_languages`.
- **N** — нет JSON-вывода с перечнем разобранных файлов.
- **P** — иначе.

**5.10.3.3 конфигурации.** Набор правил (идентификаторы и уровни), SHA-256 набора, порог и
действующие решения разметки.
- **P** — в отчёте есть сведения о правилах; **N** — нет.

Код завершения Semgrep, кроме 0 и 1, — все три артефакта N с признаком сбоя.

## 5.12.3.2 Сведения о сборочной среде и её инструментах

Шаг `env`: ОС, образ исполнителя (`ImageOS`, `ImageVersion`), Python и pip, переменные запуска,
закреплённые версии и SHA-256 инструментов и действий (`tools.json`), фактические версии
инструментов (вывод их команд версии) и дайджест образа ClamAV.
- **F** — фактическая версия инструмента не совпала с закреплённой.
- **P** — иначе (инструменты, которые не запускались, перечисляются в пояснении).

## 5.13.3.4 Журналы аудита сборки

Шаг `build-run`: команда выполняется через `bash -c`, вывод пишется в `build/build.log`; в
`build/build.json` — команда, `SOURCE_DATE_EPOCH` (время последнего коммита, если не задано),
время начала и конца, код завершения, SHA-256 журнала и каждого результата, сведения об
исполнителе и запуске; `build/SHA256SUMS` — контрольные суммы результатов.
- **P** — журнал записан (код завершения сборки отражается в решении по выпуску).

Целостность журнала защищает аттестация архива комплекта свидетельств.

## 5.13.3.5 Подтверждение хранения результатов сборки

Шаг `store-verify` в задаче `verify`: результаты загружаются из хранилища артефактов рабочего
процесса и сверяются с `build/SHA256SUMS`; записываются идентификатор, адрес и дайджест
артефакта хранилища.
- **F** — файла нет, есть лишний или контрольная сумма не совпала.
- **N** — нет контрольных сумм или сборка не дала результатов.
- **P** — все результаты совпали.

## 5.13.3.6 Подтверждение повторяемости сборки

Шаг `repro`: сравниваются `build/SHA256SUMS` и `rebuild/SHA256SUMS` — сборки на двух разных
исполнителях из одного коммита с одинаковым `SOURCE_DATE_EPOCH`.
- **F** — хотя бы один результат различается или есть только в одной сборке.
- **N** — нет результатов повторной сборки.
- **P** — результаты совпали побитово.

## 5.14.3.3 Результаты контроля целостности исходного кода

Шаг `source`:
- рабочее дерево каталога проекта совпадает с коммитом (`git status`);
- записываются коммит, хэш дерева и SHA-256 архива исходного кода (`git archive`);
- подписи коммитов диапазона проверяются через GitHub API (поле `verification`), без API —
  локально (`git log %G?`). Классы: проверена (`valid`), без подписи (`unsigned`),
  недействительна (`invalid`, `malformed_signature`, `bad_email`, `bad_cert`, `ocsp_revoked`),
  не проверяется (остальные причины).

- **F** — дерево изменено; есть недействительная подпись; при `commit_signatures: require` —
  есть коммит без проверенной подписи.
- **N** — нет репозитория git.
- **P** — иначе.

## 5.16.3.2 Перечень зависимостей ПО и 5.16.3.4 Результаты анализа заимствованных компонентов

Шаг `sca`: SBOM CycloneDX (Syft, каталог проекта) и результаты Grype по этому SBOM.

**5.16.3.2** — **P**, если в SBOM есть компоненты с идентификатором пакета (purl: имя, версия,
источник); **N** — если нет.

**5.16.3.4** — решения разметки ищутся по идентификатору уязвимости и связанным идентификаторам
(CVE ↔ GHSA) и по шаблону пакета.
- **F** — есть уязвимость не ниже порога `sca_fail_on` без решения или с решением `confirmed`.
- **P** — иначе; в пояснении — дата сборки базы уязвимостей.

## 5.17.3.5 Результаты анализа на вредоносное ПО

Шаг `av`: журнал `clamscan` (каталог проекта без `.git` и каталог установленных пакетов Python
после `install-command`), версия движка и базы сигнатур.
- **F** — найдено заражение.
- **N** — проверка не выполнялась или завершилась с ошибкой (код 2 и выше — признак сбоя).
- **P** — заражений нет.

## 5.18.3.2 Отчёт и 5.18.3.3 журналы функционального тестирования

Шаг `tests` по отчёту JUnit (`$RBPO_JUNIT`) и выводу команды тестирования.

**5.18.3.2**
- **F** — есть отказ или ошибка теста.
- **N** — тесты не запускались, в отчёте нет тестов или отчёт не получен (последнее — со сбоем,
  если команда тестирования была задана).
- **P** — все тесты пройдены (пропуски указываются).

**5.18.3.3** — **P**, если есть отчёт JUnit с тестами или журнал запуска.

## 5.20.3.2 Результаты анализа влияния неустранённых ошибок

Шаг `assemble` собирает `release/unresolved.json`: принятые срабатывания и уязвимости с
обоснованиями, ложные и недостижимые, блокирующие, ниже порогов (по уровням), отказы тестов,
истёкшие решения.
- **F** — есть срабатывание или уязвимость выше порога без решения (или подтверждённые), либо
  отказ теста.
- **N** — нет результатов ни статического, ни композиционного анализа.
- **P** — иначе.

## 5.20.3.4 Результаты проверки мер обеспечения целостности

Шаг `attest-verify`: для каждого результата сборки `gh attestation verify --repo <репозиторий>
--signer-workflow <rbpo-pipeline>/.github/workflows/rbpo.yml --source-digest <коммит>`.
- **F** — аттестация хотя бы одного результата не подтверждена.
- **N** — аттестации не создавались (запрос на слияние, `attest: false`) или нет `gh`.
- **P** — аттестации всех результатов подтверждены.

## Организационные артефакты

Шаг `org` по разделу `organizational` в `rbpo.yaml`. Для документа Markdown с якорем проверяется,
что раздел есть (якорь строится как на GitHub; подходят и `id`/`name` в HTML).
- **P** — документ (и раздел) есть; SHA-256 записан, копия — в `org/files/`.
- **N** — документа или раздела нет.

Номер артефакта проверяется по модели rbpo-evidence; артефакты, которые формирует конвейер,
документом не заменяются.
